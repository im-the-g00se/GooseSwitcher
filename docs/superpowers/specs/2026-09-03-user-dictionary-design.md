# Проектирование пользовательского словаря

## Цель этапа

Расширить существующее SQLite-хранилище и распознавание GooseSwitcher полной
поддержкой пользовательского словаря для русского и английского языков. API
должен подходить будущим GTK-настройкам и IBus-движку, не добавляя сами GTK- или
IBus-интеграции.

## Границы

В этап входят:

- модель языка и трёх типов пользовательских правил;
- строгая валидация слов и замен;
- миграция SQLite со схемы версии 1 на версию 2;
- раздельные операции создания, чтения, редактирования, поиска и удаления;
- предсказуемая обработка дубликатов и конфликтов;
- атомарный импорт и детерминированный экспорт JSON;
- использование пользовательских правил раньше системных словарей;
- unit- и интеграционные тесты нового поведения;
- документация публичного JSON-формата.

В этап не входят:

- полноценный GTK4/libadwaita-интерфейс;
- изменение алгоритма словарной автозамены после разрешения пользовательского
  правила;
- контекстная или частотная языковая модель;
- поддержка языков кроме русского и английского;
- глобальный перехват клавиатуры, systemd- или RPM-интеграция.

## Модель правила

`Language` имеет два значения: `Russian` (`ru`) и `English` (`en`). Язык
описывает письменность слова-триггера, а не язык текста замены. Поэтому правило
`ghbdtn` → `привет` имеет язык `English`.

`RuleAction` сохраняет три существующих значения:

- `ConsiderCorrect` (`consider_correct`) — считать слово корректным;
- `NeverCorrect` (`never_correct`) — никогда не исправлять слово;
- `AlwaysReplace` (`always_replace`) — всегда заменять слово указанным текстом.

`NewUserRule` представляет валидированное содержимое для создания или
редактирования. `UserRule` дополнительно содержит стабильный SQLite ID и метки
создания и изменения. Поля записи:

- `word` — отображаемое написание слова-триггера;
- `normalized_word` — внутреннее написание в Unicode lowercase;
- `language` — `Russian` или `English`;
- `action` — тип правила;
- `replacement` — текст только для `AlwaysReplace`;
- `created_at`, `updated_at` — Unix seconds UTC.

`normalized_word` хранится в SQLite для одинаковой семантики поиска,
уникальности и runtime-индекса. Уникальным ключом является пара
`(normalized_word, language)`: записи `Rust` и `rust` одного языка конфликтуют,
но одинаковое строковое значение в разных языках является отдельным ключом.

## Валидация

Слово проверяется до обращения к SQLite и повторно защищается ограничениями
схемы там, где это возможно:

- длина от 1 до 128 Unicode-символов;
- только буквы заявленного языка и внутренние соединители `-`, `‐`, `‑`, `'`,
  `’`;
- соединитель не может быть первым, последним или соседствовать с другим
  соединителем;
- английское слово содержит только ASCII `A-Z`/`a-z`, русское — буквы
  `А-Я`/`а-я` и `Ё`/`ё`;
- пробельные, числовые, смешанные и кодоподобные значения не принимаются;
- строка не обрезается и не исправляется молча.

Для `AlwaysReplace` замена должна содержать от 1 до 1024 Unicode-символов
после проверки, не начинаться и не заканчиваться пробелом и не содержать NUL
или управляющие символы. Замена может содержать несколько слов и символы обоих
языков. Для остальных действий `replacement` всегда отсутствует.

Ошибки представлены перечислением `RuleValidationError`, чтобы UI мог показать
локализованное сообщение рядом с конкретным полем без разбора текста ошибки.

## Схема SQLite и миграция

Версия схемы увеличивается до 2. Итоговая таблица:

```sql
CREATE TABLE user_rules (
    id              INTEGER PRIMARY KEY,
    word            TEXT NOT NULL,
    normalized_word TEXT NOT NULL,
    language        TEXT NOT NULL CHECK (language IN ('ru', 'en')),
    action          TEXT NOT NULL CHECK (
        action IN ('consider_correct', 'never_correct', 'always_replace')
    ),
    replacement     TEXT,
    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL,
    UNIQUE (normalized_word, language),
    CHECK (
        (action = 'always_replace' AND replacement IS NOT NULL
            AND length(replacement) > 0)
        OR
        (action <> 'always_replace' AND replacement IS NULL)
    )
);
```

Индекс `(language, normalized_word)` обслуживает точный runtime-поиск. Индекс
`(language, action, normalized_word)` поддерживает фильтры и стабильную
сортировку экрана настроек без FTS-зависимости.

Миграция 1→2 выполняется одной транзакцией:

1. создаётся таблица `user_rules_v2`;
2. старые записи читаются в Rust в порядке ID;
3. язык выводится из письменности `source`, затем запись проходит общую
   валидацию и вставляется с исходными ID и метками времени;
4. старая таблица удаляется, новая переименовывается и создаются индексы;
5. `PRAGMA user_version` меняется на 2 только при успешном завершении.

Если старая запись невалидна или две старые записи становятся одним
нормализованным ключом, миграция возвращает типизированную ошибку и полностью
откатывается. База остаётся в версии 1 без частично перенесённых данных.
Новая база версии 0 сразу получает итоговую схему версии 2. База новее версии 2
по-прежнему не открывается.

## Публичный API

Хранилище предоставляет явные операции вместо прежнего неявного upsert:

```rust
pub fn create_rule(&mut self, rule: NewUserRule)
    -> Result<UserRule, StorageError>;
pub fn update_rule(&mut self, id: i64, rule: NewUserRule)
    -> Result<Option<UserRule>, StorageError>;
pub fn get_rule(&self, id: i64)
    -> Result<Option<UserRule>, StorageError>;
pub fn find_rule(&self, language: Language, word: &str)
    -> Result<Option<UserRule>, StorageError>;
pub fn search_rules(&self, query: &RuleSearch)
    -> Result<Vec<UserRule>, StorageError>;
pub fn delete_rule(&mut self, id: i64)
    -> Result<bool, StorageError>;
```

`RuleSearch` содержит необязательные `text`, `language` и `action`, а также
`limit` и `offset`. `text` нормализуется тем же способом, что слово, и ищется
как подстрока в `normalized_word`. Результат сортируется по
`normalized_word`, затем по `language` и ID. Лимит ограничен диапазоном
1..=500; значения по умолчанию — 100 и 0.

`create_rule` никогда не перезаписывает существующую запись. Конфликт
уникального ключа становится `StorageError::DuplicateRule`, содержащим язык и
нормализованное слово. `update_rule` сохраняет ID и `created_at`, меняет
содержимое и `updated_at`, возвращая `None` для отсутствующего ID. SQL остаётся
параметризованным.

Прежний `upsert_rule` удаляется из публичного API, а внутренние и тестовые
потребители переводятся на `create_rule`. Это предотвращает случайную потерю
правила в будущем интерфейсе.

## JSON-формат

Публичный UTF-8 формат называется `gooseswitcher-user-dictionary`, версия
формата — 1:

```json
{
  "format": "gooseswitcher-user-dictionary",
  "version": 1,
  "rules": [
    {
      "word": "ghbdtn",
      "language": "en",
      "type": "always_replace",
      "replacement": "привет"
    },
    {
      "word": "Rust",
      "language": "en",
      "type": "consider_correct"
    }
  ]
}
```

ID и временные метки не экспортируются: они локальны базе и не являются
переносимым содержимым словаря. `replacement` отсутствует у правил без замены.
Неизвестные поля, имя формата, версия, язык или тип правила отвергаются, чтобы
не импортировать частично понятные данные.

Экспорт принимает `Write`, выдаёт pretty-printed JSON с завершающим переводом
строки и стабильной сортировкой по нормализованному слову и языку. Импорт
принимает `Read`, ограничивает документ 10 MiB и 10 000 правил, полностью
разбирает и валидирует его до начала изменений, затем применяет одной
транзакцией.

Дубликаты нормализованного ключа внутри одного документа всегда являются
ошибкой. Для конфликтов с существующей базой задаётся `ImportConflictPolicy`:

- `Reject` — безопасное значение по умолчанию; любой конфликт отменяет весь
  импорт;
- `Skip` — существующая запись сохраняется;
- `Replace` — существующая запись получает импортированное содержимое с
  сохранением ID и `created_at`.

Успешный импорт возвращает `ImportReport` со счётчиками `created`, `updated` и
`skipped`. Ошибка парсинга, валидации, дубликата или SQLite откатывает все
изменения.

Для реализации добавляются `serde` с `derive` и `serde_json`. Ручной JSON-парсер
не используется: он увеличил бы объём и риск обработки недоверенного импорта.

## Приоритет в распознавании

При запуске `RecognitionRuntime` загружает правила одним снимком и строит
`HashMap<(Language, String), UserRule>`. Для завершённого слова runtime:

1. соблюдает глобальный `corrections_enabled`;
2. определяет RU/EN письменность и нормализует слово;
3. применяет совпавшее пользовательское правило;
4. только при отсутствии правила выполняет существующие исключения и проверку
   системных словарей.

Таким образом, каждый из трёх пользовательских типов имеет явный приоритет над
системными словарями. Смысл существующей словарной автозамены, фильтры URL,
e-mail, путей, чисел и кодоподобных токенов не меняются. Сопоставление правил
не зависит от регистра; `AlwaysReplace` возвращает указанную пользователем
замену без преобразования регистра.

## Ошибки и целостность

Ошибки модели, JSON, ограничения размера, неподдерживаемого формата, внутренних
дубликатов, конфликтов базы, миграции и SQLite остаются различимыми вариантами
публичных error enum. Импорт и миграции не оставляют частичных изменений.
Повреждённые значения языка или типа в базе возвращают ошибку при чтении, а не
игнорируются.

## Проверка

Тесты используют настоящую временную SQLite без mock и покрывают:

- все допустимые типы и ошибки валидации;
- создание, чтение, редактирование и удаление по ID;
- регистронезависимую уникальность и точный поиск по языку;
- подстрочный поиск, фильтры, сортировку и пагинацию;
- миграцию новой базы сразу в v2;
- перенос русских и английских записей v1 с сохранением ID и меток;
- транзакционный откат невалидной или конфликтующей миграции;
- стабильный экспорт и обратный импорт всех типов;
- строгий разбор JSON, ограничения, внутренние дубликаты и три политики
  конфликта;
- атомарность импорта при ошибке;
- приоритет каждого типа пользовательского правила над системными словарями;
- сохранение существующей логики исключений и словарной автозамены без правила.

Перед завершением выполняются:

```shell
cargo fmt --check
cargo test --all-targets --features bundled-sqlite
cargo clippy --all-targets --all-features -- -D warnings
```
