# Проектирование интерфейса настроек

## Цель этапа

Добавить к GooseSwitcher отдельное нативное приложение настроек для Fedora на
GTK4 и libadwaita. Приложение использует существующие SQLite-хранилище,
валидацию пользовательских правил и JSON-формат, не переносит бизнес-логику в
виджеты и не добавляет RPM-упаковку или реализацию IBus-движка.

## Текущее состояние и границы

В репозитории уже существуют:

- `SqliteStore` с таблицами `settings` и `user_rules`;
- ключи `corrections_enabled`, `minimum_word_length` и зарезервированные ключи
  горячих клавиш;
- валидированные модели `NewUserRule`, `Language` и `RuleAction`;
- CRUD и поиск пользовательских правил;
- атомарный импорт и детерминированный экспорт строгого JSON версии 1;
- заглушка модуля `settings_ui` и пустая граница будущего IBus-адаптера.

В этап входят:

- отдельный запускаемый бинарник приложения настроек;
- управление автозаменой и минимальной длиной слова;
- поиск, создание, редактирование и удаление пользовательских правил;
- импорт и экспорт пользовательского словаря в существующем JSON-формате;
- управление списком исключённых приложений;
- проверка доступного пользователю состояния IBus и инструкция активации;
- понятное отображение ошибок;
- GTK-независимый прикладной слой и тесты его поведения;
- обновление документации по запуску и системным зависимостям UI.

В этап не входят:

- регистрация или реализация IBus-движка;
- применение исключённых приложений при обработке ввода;
- работающие горячие клавиши;
- systemd user service и RPM-упаковка;
- изменения распознавания, словарных решений или формата JSON;
- поддержка языков кроме русского и английского.

## Структура crate и зависимости

Ядро остаётся обычной библиотекой без обязательной GTK-зависимости. В
`Cargo.toml` добавляется feature `settings-ui`, включающий необязательные crates
`gtk4` и `libadwaita`. Бинарник `gooseswitcher-settings` получает
`required-features = ["settings-ui"]`. Поэтому стандартные тесты ядра не требуют
графической среды и Fedora development-пакетов, а UI собирается явной командой
с feature.

Модуль `settings_ui` делится по ответственности:

- прикладной сервис владеет `SqliteStore`, предоставляет типизированные методы
  настроек, правил, импорта и экспорта и не зависит от GTK;
- модель настроек определяет значения по умолчанию, сериализацию и валидацию;
- проверка IBus изолирует запуск пользовательских диагностических команд от
  виджетов;
- GTK-модуль, доступный только с feature `settings-ui`, строит окно и связывает
  сигналы с прикладным сервисом;
- бинарник только инициализирует `AdwApplication`, открывает SQLite по XDG-пути
  и запускает окно.

Приложение работает с базой в главном GTK-потоке. Операции единичной настройки
и пользовательского словаря малы и локальны; ввод отдельного потока и
синхронизации SQLite на этом этапе не обоснован. Выбор файлов использует
асинхронный GTK API, а разбор и транзакционное применение документа остаются в
существующем `user_dictionary`.

## Прикладной API настроек

Прикладной слой возвращает представимые в UI типы и сохраняет исходные
типизированные ошибки в цепочке `source`. Он предоставляет следующие операции:

- загрузить снимок основных параметров;
- сохранить включённость автозамены;
- сохранить минимальную длину слова;
- найти правила с существующим `RuleSearch`;
- создать, изменить и удалить правило через существующий `SqliteStore`;
- импортировать JSON с выбранной `ImportConflictPolicy`;
- экспортировать JSON в переданный путь;
- загрузить и сохранить исключённые приложения;
- получить снимок состояния IBus.

Минимальная длина ограничивается диапазоном `1..=64`. Нижняя граница исключает
бессмысленное автоматическое исправление пустых токенов, верхняя сохраняет
удобный диапазон контрола и не меняет алгоритм распознавания. Старое сохранённое
целое вне диапазона считается ошибкой конфигурации и показывается пользователю,
а не исправляется молча.

Ключ `excluded_applications` хранит JSON-массив строк в существующей таблице
`settings`. Идентификатор приложения после удаления внешних пробелов должен
быть непустым, не длиннее 255 Unicode-символов, не содержать управляющих
символов. Сервис удаляет точные дубликаты, сохраняет стабильный порядок и не
позволяет виджетам вручную собирать JSON. Формат базы и номер схемы не меняются,
поскольку таблица `settings` уже предназначена для сериализованных значений.

## Основное окно

Приложение использует нативный `AdwPreferencesWindow` с четырьмя страницами.
Подписи и сообщения пользовательского интерфейса — на русском языке.

### Основные

Страница содержит:

- `AdwSwitchRow` «Автоматически исправлять слова»;
- строку минимальной длины с числовым контролом от 1 до 64;
- пояснение, что уже запущенный движок считывает изменения после перезапуска.

Значения сохраняются сразу после изменения. При ошибке сохранения контрол
возвращается к последнему подтверждённому значению, а окно показывает toast с
понятным сообщением и технической причиной в дополнительных деталях.

### Пользовательский словарь

Страница содержит строку поиска, фильтры языка и типа правила, прокручиваемый
список и действия «Добавить», «Импортировать» и «Экспортировать». Поиск вызывает
существующий `RuleSearch`; первая версия экрана показывает до 500 совпадений и
не вводит отдельную пагинацию.

Каждая строка отображает слово, язык, понятное название действия и замену, если
она есть. Активация строки открывает один диалог для создания или
редактирования. Диалог содержит слово, язык, тип правила и условно видимое поле
замены. Он строит `NewUserRule` и показывает `RuleValidationError` возле
соответствующего поля. Сохранение вызывает `create_rule` или `update_rule`; UI
не повторяет правила допустимых символов, языков или замены.

Удаление требует подтверждения с названием слова. После успешного создания,
изменения, удаления или импорта текущий список перечитывается из SQLite, чтобы
виджеты не становились вторым источником истины.

Экспорт открывает нативный диалог сохранения с расширением `.json` и вызывает
существующий `export_json`. Импорт сначала предлагает политику конфликтов:
остановить импорт, пропустить существующие или заменить существующие. Затем
нативный диалог открытия передаёт файл существующему `import_json`. Успешный
импорт показывает количество созданных, обновлённых и пропущенных правил;
ошибка не меняет список, поскольку импорт уже транзакционен.

### Исключённые приложения

Страница показывает сохранённые идентификаторы приложений, поле добавления и
удаление отдельной строки с подтверждением. Подзаголовок приводит понятные
примеры идентификаторов и честно сообщает, что до реализации IBus-адаптера
список сохраняется, но ещё не влияет на обработку ввода.

### IBus

Страница показывает одно из состояний:

- движок зарегистрирован и активен;
- движок зарегистрирован, но сейчас не выбран;
- движок не зарегистрирован;
- состояние нельзя определить с объяснением причины.

Проверка использует пользовательские команды IBus без повышения привилегий и
без изменения состояния системы. Кнопка «Обновить» повторяет проверку. Экран
не утверждает, что пустая текущая заглушка является установленным движком.

Инструкция объясняет, что после появления и установки IBus-компонента нужно
открыть «Параметры → Клавиатура → Источники ввода», добавить GooseSwitcher и
выбрать его как источник ввода. Поскольку этот этап не создаёт компонент IBus
или RPM, инструкция также прямо сообщает, что в текущей исходной сборке
регистрация ещё отсутствует.

## Горячие клавиши

Текущий `ibus`-модуль не обрабатывает события, а три константы конфигурации не
образуют поддерживаемой архитектуры горячих клавиш. Поэтому этот этап не
показывает редактируемые контролы, которые ничего не делают. Страница IBus
кратко сообщает, что настройка сочетаний станет доступна после реализации
действий «исправить», «отменить» и «временно отключить» внутри IBus-движка.

## Ошибки и восстановление

Ошибки делятся на три уровня:

- ошибки ввода правила или идентификатора приложения отображаются возле поля и
  сохраняют введённые данные;
- ошибки SQLite и файлов показываются toast или диалогом, действие можно
  повторить, приложение продолжает работу;
- ошибка открытия основной базы показывается в отдельном окне с причиной и
  возможностью закрыть приложение без panic.

Пользовательские тексты описывают действие и способ восстановления. Полный
`Display` исходной ошибки доступен в подробностях, но не заменяет понятный
заголовок. Отмена файлового диалога не считается ошибкой.

## Тестирование

Unit-тесты GTK-независимого слоя используют настоящую временную SQLite и
покрывают:

- значения по умолчанию и чтение сохранённых основных параметров;
- отклонение испорченных bool, целого и значения вне `1..=64`;
- точную сериализацию сохранённых основных параметров;
- проверку, удаление дубликатов и стабильный JSON списка приложений;
- создание, изменение, поиск и удаление правил через сервис;
- передачу каждой политики конфликта импорта и отчёт результата;
- экспорт через прикладной API;
- разбор успешного, неактивного, отсутствующего и ошибочного состояния IBus
  через тестируемую функцию интерпретации вывода команд.

Существующие тесты модели, SQLite и JSON остаются источником доказательства
бизнес-правил. GTK-слой не дублирует эти сценарии; для него обязательны успешная
компиляция feature и ручная проверка окна в графической Fedora-сессии.

Перед завершением выполняются:

```shell
cargo fmt --check
cargo test --all-targets
cargo clippy --all-targets --all-features -- -D warnings
cargo check --features settings-ui --bin gooseswitcher-settings
```

Если GTK4/libadwaita development-пакеты отсутствуют в рабочем окружении,
невозможность двух feature-команд фиксируется отдельно с точной ошибкой
`pkg-config`; проверки независимого ядра всё равно должны пройти. Для Fedora в
README документируются необходимые пакеты разработки и команда запуска.
